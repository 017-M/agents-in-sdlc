GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、その作業をリアルタイムで確認できます。すべてのツール呼び出しやファイルの編集を追跡し、差分を確認して個別の変更を採用または取り消したり、エディターを離れずに追加のプロンプトを送って会話を進めたりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで確認します。
- 提案されたファイルの編集をレビューして採用します。
- セッション中にエージェントをガイドし、ハイコントラストモードに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替え機能も追加します。新しい会話を始めるのではなく、既存のセッションをガイドして作業を広げます。

## Copilot の進捗を確認する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調べているファイル、実行するコマンド、提案する編集などを確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの操作を確認します。ファイルの読み込みや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、チャット内に差分が表示されます。
    - 変更を採用するには **Keep** を選択します。
    - 変更を取り消してエージェントにもう一度試させるには **Undo** を選択します。
4. チャットの上部にある **Files changed** を開くと、このセッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. ハイコントラストモードの実装が完了するまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようエージェントをガイドする

ハイコントラストモードができたら、同じ会話でライトモードの切り替え機能を追加します。同じチャットセッションを続けることで、エージェントは変更したコンポーネント、スタイルの方針、local storage を使った設定の保存方法など、これまでのコンテキストを保持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードと同様に、新しい編集を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが意図しない方針を取った場合は、たとえばトグル UI を変更しようとしたときに、チャット入力欄の横にある **Stop** ボタンで停止し、意図を説明する追加のメッセージを送信します。

> [!TIP]
> 作業中のセッションをガイドするほうが、最初からやり直すより短時間で済みます。追加プロンプトで調整を依頼できます。たとえば、「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」、「トグルを 3 つ追加せず、ライトモードを既存の設定パネルに組み込む」、「両方のトグルにキーボードショートカットも追加する」などと指示します。

## 変更されたファイルを確認する

変更をコミットする前に、エージェントが編集したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存など、カスタムエージェントが指定したアクセシビリティのパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを確認し、ガイドしました。ファイルの編集を確認して採用または取り消し、コンテキストを失わずに追加のプロンプトを送って作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する方法。
- 個々のファイル編集を採用または取り消す方法。
- 追加プロンプトを使って、作業中のセッションをガイドする方法。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
