フィルター機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストが、1 つのブランチに保存されています。まとめてレビューし、プルリクエストを開きましょう。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は**Agent Merge**にプロセスを管理してもらいます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分けます。ワークショップを簡潔にするため、フィルター機能と品質向上の作業は同じセッションとブランチで進め、この PR にまとめました。

このレッスンでは、次のことを行います。

- Agent Merge と、マージまでの作業を自動化する方法を学びます。
- 機能全体の PR と検証の証拠を確認します。
- レビュー後にのみ Agent Merge を承認し、PR がマージされたことを確認します。

## シナリオ

フィルター機能の作業を通して、Copilot を使って機能を計画、実装、検証しました。Tailspin Toys では、マージを許可する権限は開発者が保持したまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge について

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージするために必要な残りの作業を自動化します。有効にすると、app のセッションがプルリクエストを読み取り、失敗した継続的インテグレーション (CI) チェックの修正、レビューコメントへの対応、必要な場合のリベースなど、マージを妨げている問題に取り組みます。GitHub が許可すると PR をマージします。バックグラウンドで実行され、アプリを再起動しても継続し、PR がマージされると自動的に停止します。

これまでは、自分で **Merge pull request** を選択していました。Agent Merge にその役割を任せることもできますが、コードの編集やマージには明示的な承認が必要です。マージを許可する前に、許可する操作と作業内容を確認してください。

## Agent Merge で PR を管理する

コードの作成とレビューが終わったら、Agent Merge に PR のプロセスを管理してもらいましょう。

1. エージェントピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウンの選択だけでは始まりません。

Agent Merge が開始され、次の処理を行います。

- タイトルと説明を含むプルリクエストを作成します。
- Issue からセッションを開始した場合は、説明の本文で関連する Issue を参照します。
- ターゲットブランチへのリベースや、マージ競合に対処します。
- CI を監視し、すべてのチェックが成功することを確認します。
- 他の開発者や Copilot code review からのフィードバックを確認し、コメントを解決するために変更を加えます。
- 必要に応じて、すべてのチェックが成功した後に PR を自動的にマージします。

すべてのチェックに成功した後、Agent Merge に PR もマージしてもらいます。

5. マージを許可する前に、PR の差分と検証の証拠を確認します。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** にチェックが付いていることを確認します。
8. エージェントに明示的にマージを依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. 進捗を確認し、報告された問題を解決します。続行前に、PR の状態が **Merged** になっていることを確認します。マージの許可を有効にしたことやエージェントが実行中であることは、マージが完了した証拠にはなりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護やアクセス許可の不足を回避しません。続行前にこれらの問題を解決してください。
